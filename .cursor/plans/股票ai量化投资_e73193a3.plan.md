# 股票 AI 量化投资功能 — 调整版实施计划（fund 工程）

## 一、调整目标

- 保留：股票代码标的、周期审核、管理端建单、完成后用户可见、手续费。
- 删除：现货钱包概念、量化钱包概念、任何划转动作。
- 新口径：资金全部在 `app_user_wallet` 维度核算；新增 AI 量化相关字段，用于冻结本金、释放本金、记账统计。

---

## 二、核心业务口径（重定义）

1. 用户预约 AI 量化时，不做跨钱包划转，只在 `app_user_wallet` 扣减可用并增加“量化冻结金额”。
2. 周期审核通过后，管理员基于股票 `stock_id` 建展示订单。
3. 周期完成时：
   - 按订单计算盈亏。
   - 本金从“量化冻结金额”释放回可用余额。
   - 盈利（或亏损）直接作用到 `app_user_wallet.available_balance`。
   - 若盈利为正，按费率扣手续费（同一钱包内扣减）。
4. 用户仅在周期完成后看到该订单（`user_visible=1`）。

## 六、详细开发步骤（每步含代码与功能）

### 约定：事务采用 RedisLockService.lockTransaction（禁止使用 @Transactional）

- AI 量化相关 **写库/资金** 流程 **不使用** `@Transactional(rollbackFor = [Exception::class])`。
- 与 [`common/src/main/kotlin/com/fund/utils/RedisLockService.kt`](common/src/main/kotlin/com/fund/utils/RedisLockService.kt) 保持一致：外层使用 **`RedisLockService.lockTransaction(lockKey) { ... }`**，在内置 **`PlatformTransactionManager`** 上做提交/回滚，并结合 Redisson **写锁** 控制并发。
- **锁键建议**：
  - 用户维度串行：`RedisKeys.LOCK_AI_QUANT_CYCLE + userId`（如预约）。
  - 同一周期维度串行：`RedisKeys.LOCK_AI_QUANT_ORDER + cycleId`（如管理端审核、驳回、完成、绑定订单等写操作）。
- `AppUserWalletV2ServiceImpl` 中新增的冻结/释放/盈亏方法 **仅实现业务**，**不写** `@Transactional`；事务边界一律由调用方 `lockTransaction` 包住，避免双重事务声明。

### 步骤3：`AppAiQuantCycleServiceImpl`

#### 功能
- 实现预约、审核、驳回、完成四个关键流程。

#### 关键方法与代码

```kotlin
/**
 * 用户预约。
 * 仅冻结本金；事务与分布式写锁由 lockTransaction 统一处理。
 */
fun submitReserve(userId: Long, req: AiQuantReserveReq): R<Any> {
    val lockKey = RedisKeys.LOCK_AI_QUANT_CYCLE + userId
    return RedisLockService.lockTransaction(lockKey) {
        // 1) 校验全局最小预约金额与钱包可用余额
        // 2) freezeAiQuantPrincipal(...)
        // 3) 插入 cycle，phase = 0
        R.success()
    }
}

/**
 * 审核驳回。
 * 释放冻结本金回可用余额；按周期维度加锁。
 */
fun auditReject(cycleId: Long, adminId: Long, reason: String): R<Any> {
    val lockKey = RedisKeys.LOCK_AI_QUANT_ORDER + cycleId
    return RedisLockService.lockTransaction(lockKey) {
        // 1) 加载 cycle，校验 phase = 0
        // 2) releaseAiQuantPrincipal(冻结金额按业务口径取 requestAmount 或实际冻结额)
        // 3) 更新 cycle：phase = -1，reject_reason
        R.success()
    }
}
```

### 步骤4：`AppAiQuantOrderServiceImpl`

#### 功能
- 基于 `stock_id` 建单并计算订单盈亏。

#### 建单核心规则
- `cycleId` 必填。
- `stockId` 必填，查 `StockService` 填 `symbol/market/stockName`。
- `buyAmount == cycle.approvedAmount`。
- `feeRate` 从全局配置快照。
- `userVisible=0`。

#### 盈亏计算代码

```kotlin
/**
 * 计算并落库盈亏与手续费。
 */
fun calcAndSaveProfit(order: AppAiQuantOrder): AppAiQuantOrder {
    val qty = order.buyAmount!!.divide(order.buyPrice!!, 16, RoundingMode.HALF_UP)
    val profit = order.sellPrice!!.subtract(order.buyPrice!!).multiply(qty).setScale(16, RoundingMode.HALF_UP)
    val fee = if (profit > BigDecimal.ZERO) profit.multiply(order.feeRate ?: BigDecimal.ZERO).setScale(16, RoundingMode.HALF_UP) else BigDecimal.ZERO
    order.positionQty = qty
    order.profitAmount = profit
    order.profitRate = if (order.buyAmount!! > BigDecimal.ZERO) profit.divide(order.buyAmount, 16, RoundingMode.HALF_UP) else BigDecimal.ZERO
    order.feeAmount = fee
    return order
}
```

### 步骤5：周期完成 `finishCycle`

#### 功能
- 释放本金、结算盈亏、扣手续费、开放可见。

#### 完成流程代码（核心）

```kotlin
fun finishCycle(cycleId: Long, adminId: Long): R<Any> {
    val lockKey = RedisKeys.LOCK_AI_QUANT_ORDER + cycleId
    return RedisLockService.lockTransaction(lockKey) {
        // 1) 校验 cycle.phase == 1 且 linkedOrderId 不为空
        // 2) 读取订单并校验 sellPrice / sellTime 已填
        // 3) calcAndSaveProfit(order)

        // 4) 释放本金
        walletService.releaseAiQuantPrincipal(
            cycle.userId!!, "USDT", cycle.approvedAmount!!,
            GoldChangeEnum.AI_QUANT_PRINCIPAL_RELEASE, "AI量化周期完成释放本金"
        )

        // 5) 结算盈亏（正负都结）
        walletService.settleAiQuantProfit(
            cycle.userId!!, "USDT", order.profitAmount!!,
            GoldChangeEnum.AI_QUANT_PROFIT_SETTLE, "AI量化盈亏结算"
        )

        // 6) 扣手续费（仅盈利时）
        if (order.feeAmount!! > BigDecimal.ZERO) {
            walletService.settleAiQuantProfit(
                cycle.userId!!, "USDT", order.feeAmount!!.negate(),
                GoldChangeEnum.AI_QUANT_FEE_DEDUCT, "AI量化手续费扣减"
            )
        }

        // 7) 更新钱包统计 ai_quant_total_profit / ai_quant_total_fee
        // 8) order.userVisible = 1
        // 9) cycle.phase = 2，cycle.profitAmount = profit - fee，cycle.feeAmount = fee
        R.success()
    }
}
```

## 七、优化点（代码层）

1. 所有金额字段统一 `BigDecimal(32,16)`，统一 `HALF_UP`。
2. 所有资金类写操作外层使用 **`RedisLockService.lockTransaction`**（搭配 `RedisKeys.LOCK_AI_QUANT_*`），**不写** `@Transactional`，避免并发穿透并与项目事务风格一致。
3. `finishCycle` 设计为唯一的“订单可见开关”，避免多入口导致数据错位。
4. 建单时做费率快照，确保后续全局费率变更不影响历史订单。
5. 在 Service 方法中补完整中文注释，明确输入、状态流转与资金影响。

## 八、验收标准

1. 预约成功后：`app_user_wallet.ai_quant_freeze` 增加，可用余额减少。
2. 驳回后：`ai_quant_freeze` 归还，可用余额恢复。
3. 审核通过 + 建单 + 完成后：
   - 本金释放；
   - 盈亏与手续费正确入账；
   - `cycle.phase=2`；
   - `order.user_visible=1`。
4. 全流程不出现“跨钱包划转”字段和方法调用。
